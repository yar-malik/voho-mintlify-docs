Two endpoints for checking text *before* it reaches a caller. Both are free — they do not synthesise audio and do not draw down credits.

## Normalize

<Info>
  **POST** `https://app.voho.ai/v1/text/normalize`
</Info>

Returns the text as it will actually be spoken, with numbers, currency, and abbreviations expanded.

This exists because expansion is where surprises live. "SAR 1,250" read out as digits is the kind of thing that gets noticed on a live call, and you want to catch it in development rather than in production.

<ParamField body="text" type="string" required>
  Text to expand.
</ParamField>

<ParamField body="lang" type="string">
  `ar` or `en`. Detected automatically when omitted.
</ParamField>

<RequestExample>
```bash cURL
curl -X POST https://app.voho.ai/v1/text/normalize \
  -H "Authorization: Bearer $VOHO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"المبلغ SAR 1,250 مستحق في 15/03."}'
```
</RequestExample>

<ResponseExample>
```json Response
{
  "original": "المبلغ SAR 1,250 مستحق في 15/03.",
  "normalized": "المبلغ ألف ومئتان وخمسون ريال سعودي مستحق في خمسة عشر مارس.",
  "language": "ar",
  "replacements": [
    { "from": "SAR 1,250", "to": "ألف ومئتان وخمسون ريال سعودي" },
    { "from": "15/03", "to": "خمسة عشر مارس" }
  ]
}
```
</ResponseExample>

<Tip>
  Run your templates through this once during development. Most pronunciation complaints trace back to an expansion nobody looked at.
</Tip>

## Coverage

<Info>
  **POST** `https://app.voho.ai/v1/text/coverage`
</Info>

Flags tokens likely to be mispronounced: Latin words inside Arabic text, unexpanded digits, asset tags, and acronyms.

<Warning>
  This is a lexical check, not a pronunciation model. It tells you where a pronunciation hint is probably needed; it does not know how your asset codes are meant to sound.
</Warning>

<ParamField body="text" type="string" required>
  Text to check.
</ParamField>

### Flag reasons

| Reason | Meaning |
| --- | --- |
| `asset_tag` | Looks like an equipment code — spell out or supply a hint |
| `acronym` | Will be read letter by letter unless hinted |
| `contains_digits` | Will be expanded; the hint shows how |
| `latin_in_arabic` | Latin word inside Arabic text; confirm the intended reading |

<RequestExample>
```bash cURL
curl -X POST https://app.voho.ai/v1/text/coverage \
  -H "Authorization: Bearer $VOHO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"عطل في المكيف AC-4417 في مبنى HVAC"}'
```
</RequestExample>

<ResponseExample>
```json Response
{
  "language": "ar",
  "token_count": 6,
  "flagged_count": 2,
  "coverage": 0.667,
  "flagged": [
    {
      "token": "AC-4417",
      "reason": "asset_tag",
      "hint": "Spell out or supply a pronunciation hint."
    },
    {
      "token": "HVAC",
      "reason": "acronym",
      "hint": "Will be read letter by letter unless a hint is supplied."
    }
  ]
}
```
</ResponseExample>

`coverage` is the proportion of tokens that raised no flag — 1.0 means nothing looked risky. Treat it as a smoke test on a batch of templates, not a quality score.
