Two model tiers. Both cover the whole voice catalog; they differ in fidelity, speed, and price.

<CardGroup cols={2}>
  <Card title="Sada — sada-1" icon="star">
    **Flagship expressive model.** Highest fidelity, full emotional range. The default.
  </Card>
  <Card title="Nabra — nabra-1" icon="gauge-high">
    **Fast and economical.** Built for high-volume production traffic.
  </Card>
</CardGroup>

## Comparison

| | `sada-1` | `nabra-1` |
| --- | --- | --- |
| Positioning | Flagship, expressive | Economy, high volume |
| Cost per 1,000 characters | 5 cents | 2 cents |
| Streaming | Yes | No |
| WebSocket | Yes | No |
| `pitch` parameter | Ignored | Supported |
| Default | Yes | — |

## Choosing

**Use `sada-1`** for anything a customer hears in a live conversation. It is the default, it is the only tier with a streaming path, and expressiveness matters most exactly where latency does.

**Use `nabra-1`** for bulk generation where cost dominates and nothing is waiting on the result — pre-rendering prompt libraries, generating notification audio in batch, non-realtime pipelines. At 2 cents per 1,000 characters it is 60% cheaper.

<Warning>
  `nabra-1` cannot stream. [`/v1/speech/stream`](/api-reference/speech-stream) and the [WebSocket](/api-reference/websocket) accept `sada-1` only, and reject other models up front rather than failing mid-stream.
</Warning>

## Pitch

`pitch` applies only to `nabra-1`. The flagship tier ignores it — its expressiveness comes from the model rather than from post-hoc adjustment, and a pitch-shifted flagship voice would sound worse, not more configurable.

```json
{
  "text": "Welcome to Voho",
  "voice": "cupola",
  "model": "nabra-1",
  "pitch": -2.0
}
```

Use `speed` for pacing on either tier.

## Cost

Cost is per 1,000 characters, rounded up, so a very short request still costs at least one cent.

| Characters | `sada-1` | `nabra-1` |
| --- | --- | --- |
| 100 | 1¢ | 1¢ |
| 1,000 | 5¢ | 2¢ |
| 10,000 | 50¢ | 20¢ |
| 100,000 | $5.00 | $2.00 |

Every synthesis response returns `X-Voho-Characters` and `X-Voho-Cost-Cents`, so you can attribute spend per request without a separate usage call.

<Tip>
  Rounding up means many tiny requests cost more than the same text batched. If you are generating a prompt library, synthesise whole prompts rather than fragments.
</Tip>
